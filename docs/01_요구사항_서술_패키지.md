**범위**: `src` 학습 시스템 (C++17, Boundary/Control/Entity, Catch2 TDD)  
**금지**: 구현·소스 코드·빌드 스크립트

---

## Level 1 — Epic

### 제목
**확장 가능한 C++ Feedback Analyzer 학습 시스템**

### 목적 (4줄)

1. 규칙 기반 피드백 감정·카테고리 분석을 **단일 Registry·Converter** 로 수행하고, 집계·필터·출력 경로 간 결과 불일치를 제거한다.
2. Boundary(HTTP·검증·Presenter) / Control(유스케이스) / Entity(판별·집계) **Dual-Track** 으로 레이어를 분리해 OCP·SRP를 학습 가능한 구조로 만든다.
3. 입력·출력·실패를 **계약(schema·error.code)** 으로 고정하고 Catch2 RED-GREEN-REFACTOR로 회귀를 차단한다.
4. JSON/YAML 설정·동적 감정 등록으로 **기존 분류 코드 변경 없이** 분석 단위를 확장하는 경험을 제공한다.

### 성공 기준 (측정 가능)

| ID | 기준 | 측정 방법 | 목표값 |
|----|------|-----------|--------|
| SC-01 | Domain 테스트 커버리지 | gcov/llvm-cov, `tests/domain` | line ≥ 95%, branch ≥ 90% |
| SC-02 | Boundary·Data·전체 커버리지 | 동일 도구, 레이어별 | boundary line ≥ 85%; data line ≥ 90%; overall line ≥ 90% |
| SC-03 | 계약 테스트 통과 | Catch2 태그 `[boundary]` `[domain]` `[data]` 전부 GREEN | 100% pass, 0 skip |
| SC-04 | Invariant 회귀 | 골든 피드백 N≥20 + `classify`/`aggregate`/`filter` 일치 IT | 불일치 0건 |
| SC-05 | 에러 코드 동결 | `error.code` 변경 시 버전 태그·테스트 갱신 PR 필수 | main 브랜치 undocumented change 0건 |
| SC-06 | Gherkin 정합 | Level 4 시나리오(GH-01~13, README-01~08) ↔ Catch2 매핑 누락 0 | Traceability Matrix 100% 행 매핑 |
| SC-07 | 금지 패턴 | 정적 검토: 전역 mutable 분석 상태, 이중 SENTIMENT, Domain 내 cout | 0건 |

### 회귀 정책

- 골든 픽스처·`error.code`·공개 Domain API 변경 → **테스트·Gherkin·Matrix 동시 갱신** 없으면 merge 불가.
- RED 상태에서 구조 리팩터 금지; REFACTOR는 전체 Catch2 GREEN 후만.
- 레거시 TextAnalyzer/Filters 이중 키워드를 기대 기준으로 사용 금지.

## Level 3 — User Stories

### ST-01 입력 검증 (잘못된 형식)

**As a** 학습자  
**I want** 텍스트·라벨:본문·CSV 입력이 계약 위반 시 명시적 오류를 받고  
**So that** 조용한 실패 없이 RED 테스트로 계약을 고정할 수 있다.

**Acceptance Criteria**

- [ ] 빈 문자열·공백만 입력 시 `EMPTY_TEXT`, HTTP 400, `field=text`
- [ ] `:` 없음·라벨/본문 공백 시 파싱 실패 코드 반환(세션 건수 불변)
- [ ] CSV 헤더에 `text` 없으면 `CSV_MISSING_TEXT_COLUMN`, HTTP 422
- [ ] Boundary 테스트가 Domain 없이 Validator·ErrorMapper만 검증

---

### ST-02 감정 Hub 기반 정확한 형식 변환

**As a** 학습자  
**I want** 피드백당 긍정·부정·중립 중 정확히 하나의 감정으로 형식화하고  
**So that** 집계·필터·단건 결과가 항상 일치한다.

**Acceptance Criteria**

- [ ] 미매칭 키워드 → Hub `중립` (INV-D2, INV-D3)
- [ ] 우선순위: 긍정 → 부정 → Hub (공존 문장 골든 테스트 통과)
- [ ] `aggregate` 감정 건수 합 = 입력 건수 (INV-D5)
- [ ] 동일 텍스트 2회 `classify` 결과 동일 (INV-D1)

---

### ST-03 레지스트리 OCP — 새 감정 추가 시 기존 코드 무변경

**As a** 학습자  
**I want** `registerUnit`으로 새 감정 Unit을 등록하고  
**So that** Converter if-else 분기 추가 없이 분류가 확장된다.

**Acceptance Criteria**

- [ ] `registerUnit` 성공 후 해당 키워드 문장 분류 반영
- [ ] 중복 `(type, unitId)` → `DUPLICATE_UNIT`, Registry 이전 스냅샷 유지
- [ ] 기존 긍·부·중 골든 테스트 GREEN 유지(의도 변경 없는 한)
- [ ] Converter 소스에 감정별 하드코딩 분기 0건

---

### ST-04 출력 포맷 선택 (JSON / CSV / 표)

**As a** 학습자  
**I want** 동일 분석 스냅샷을 JSON·CSV·HTML 표로보내고  
**So that** Presenter만 추가해 출력 채널을 확장한다.

**Acceptance Criteria**

- [ ] JSON: `sentimentStats`, `categoryStats`, `feedbacks` 경로 존재, id+count 스키마
- [ ] CSV: 헤더 `text` 단일 열, 필터 결과 행 수 = 데이터 행 수
- [ ] HTML 표: 행 수 = 피드백 수, `<script>` 미이스케이프 0건
- [ ] `fil_data` 비어 있을 때 `NO_DATA_TO_EXPORT`, HTTP 404

---

### ST-05 설정 파일(JSON/YAML) 로드 실패 처리

**As a** 학습자  
**I want** `loadRatios` 실패 시 기동·로드 중단과 명확한 오류를 받고  
**So that** 잘못된 Hub·중복 Unit이 런타임 분류를 오염시키지 않는다.

**Acceptance Criteria**

- [ ] 중복 unit id → `DUPLICATE_UNIT`
- [ ] Hub 누락/우선순위 불일치 → `INVALID_HUB_CONFIG`
- [ ] `version` 미지원 → `UNSUPPORTED_CONFIG_VERSION`
- [ ] 파싱 실패 → `CONFIG_PARSE_ERROR`; 실패 시 Registry 변경 없음

---

### ST-06 동적 감정 등록

**As a** 학습자  
**I want** 런타임에 새 감정 Unit·키워드를 등록하고  
**So that** 재배포 없이 분석 축을 확장한다(Control API 또는 관리 UC).

**Acceptance Criteria**

- [ ] 등록 직후 `classify`가 새 Unit 반영
- [ ] `UNKNOWN_EMOTION`은 명시 라벨 파싱 실패에만 사용; Hub로 대체 금지
- [ ] 등록 실패 시 이전 Registry 스냅샷 불변
- [ ] 동적 등록 후에도 INV-D1·D6 필터 정합성 유지

Feature: README premises — feedback collection, classification, visualization, export

  Background:
    Given the Feedback Analyzer server is running at "http://localhost:8080"
    And the session feedback list is empty

  @README-01
  Scenario: Dashboard first visit shows input and upload forms
    When the user sends GET "/"

    When the user posts feedback text to "/analyze"

    And the sum of sentiment counts should equal the session feedback count

  @README-04
  Scenario: Filter by negative sentiment and delivery category then download CSV
    When the user posts sentiment filter "부정" and keyword filter "배송" to "/filter"
    Then the filtered result count should be 1
    When the user sends GET "/download"
    Then the CSV data row count should match the filtered result count
